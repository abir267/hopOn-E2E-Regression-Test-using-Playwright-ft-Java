Confirmed Bugs (4)

1. Restaurant "Not Accepting Orders" does not block checkout High
Test: RestaurantNotAcceptingOrdersTest — currently FAILING (asserts the fix, not the bug)
Toggling the restaurant to "Not Accepting Orders" in admin does not stop the customer app from ordering. No closed/unavailable indicator anywhere — menu, item cards, "+" button, checkout all behave as if the restaurant were open. Checkout completes and a real order is placed.
First confirmed live 2026-09-23, real order #01E-AA0 on QA Burger Express [AA].
2. Menu item "Not Available" does not block ordering it High
Test: MenuItemNotAvailableTest — currently FAILING (asserts the fix, not the bug)
Same gap as bug 1, at the item level. Marking "Crispy Burger" Not Available in Menu Management does not hide it or block it on the customer menu — size modal, Add to Cart, and full checkout all work normally for a supposedly-unavailable item.
First confirmed live 2026-09-23, real order #01E-B04 on QA Burger Express [AA], item "Crispy Burger".
3. No validation message when restaurant goes offline after item is already in cart High
Test: NoValidationMessageOnCheckoutTest — currently passing (documents the bug)
Same root cause as bugs 1 & 2, exact reported repro order: add item to cart first, restaurant goes offline second, then attempt checkout. No "unavailable"/"closed"/"not accepting" message appears anywhere on the checkout page — order #023-5A1 placed silently in the latest run.
Screenshot: target/bug-evidence/issue6_no_validation_on_checkout.png
4. "Cancel Order" shows no confirmation — Lucide icon crash High
Test: CancelOrderModalBrokenTest — currently passing (documents the bug)
Clicking "Cancel Order (Valid within 3 mins)" on the tracking page does nothing visible at all — no modal, popup, or toast. Root cause is a JS crash, captured via browser console on every run: 
ERROR Error: The "Cancel" icon has not been provided by any available icon providers.
    at LucideAngularComponent.ngOnChanges (chunk-SUE2ULFI.js:27382)
    at ToastNotification_Template (main-BJWT6IB2.js:3505)
The cancel-confirmation toast tries to render a Lucide "Cancel" icon that isn't registered with any icon provider, so the Angular template throws and the whole toast silently fails to render.
Screenshot: target/bug-evidence/issue4_cancel_order_modal_broken.png
5. Stale "Cancel Order" button after restaurant-side cancellation Minor
Test: RestaurantCancelsOrderTest — currently passing (documents the bug)
When the restaurant cancels from admin, the customer's already-open tracking page (no reload) correctly shows an "Order Cancelled" banner live — but the "Cancel Order (Valid within 3 mins)" button stays visible and clickable on an order that's already cancelled. Also: it's an inline banner only, no popup/toast, so a customer who has navigated away gets no attention-grabbing notification.
Screenshot: target/bug-evidence/issue1_restaurant_cancels_order.png

Investigated, Not Reproduced

Cart badge/basket misplacement on delivery-location change
