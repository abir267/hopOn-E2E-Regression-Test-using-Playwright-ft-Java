3 Build — wiring it into the Java project

utils/MqttListener.java
Switched from the originally-planned Paho MQTT v3 client (already used by the sibling mobile Appium project) to HiveMQ's MQTT client, because the real web app speaks MQTT v5 over WebSocket — Paho's mqttv3 module supports neither.

Added MqttListener.connectFromWebSession(Page page): reads _ssl_mt/_ssl_mu/_ssl_taf straight off the Playwright BrowserContext's cookies and _ssl_mcid from localStorage via page.evaluate(), then connects and subscribes — mirroring exactly what the real Angular service does, with zero hardcoded/guessed session values.

4 Live test — two real bugs found and fixed

Bug 1 Connected to localhost instead of the real broker
Caused by: com.hivemq.client.mqtt.exceptions.ConnectionFailedException: io.netty.channel.AbstractChannel$AnnotatedConnectException: Connection refused: no further information: localhost/127.0.0.1:1883
Root cause: a .transportConfig(MqttClientTransportConfig.builder()...) call, added to give the connect a timeout, built a brand-new transport config object — which silently discarded the .serverHost()/.serverPort()/.webSocketConfig()/.sslWithDefaultConfig() set earlier in the same fluent chain, resetting everything to the library's hardcoded default (localhost:1883, no TLS, no WebSocket). Compiled fine — only failed at runtime.

Fix: removed the separate .transportConfig(...) call. Kept the timeout goal by wrapping the async connect call itself in .get(15, TimeUnit.SECONDS) instead.
Bug 2 Missing WebSocket codec — NoClassDefFoundError
java.lang.NoClassDefFoundError: io/netty/handler/codec/http/websocketx/WebSocketVersion at com.hivemq.client.internal.mqtt.handler.websocket.MqttWebSocketInitializer.initChannel
This one got further — TLS handshake to the real broker succeeded — then failed initializing the WebSocket layer. hivemq-mqtt-client marks WebSocket support as an optional transitive dependency; io.netty:netty-codec-http (which owns WebSocketVersion) isn't pulled in on its own. Again: compiled clean, broke only at connect time.

Fix: added io.netty:netty-codec-http explicitly to pom.xml, pinned to 4.1.99.Final to match the netty version hivemq-mqtt-client already pulls in for its other modules (confirmed via mvn dependency:tree).
